# 설문 집계기 계획서

## 목표

엑셀에서 머리글 줄까지 복사해 붙여넣으면 문항별 결과 표를 보여 주는 `index.html` 한 파일짜리 집계기.

## 지켜야 할 조건

- **파일 하나:** 화면, 스타일, 계산 로직을 모두 `index.html` 안에 넣는다. 외부 라이브러리, 외부 글꼴, 분석 도구는 쓰지 않는다.
- **데이터는 브라우저 안에서만:** 붙여넣은 데이터를 네트워크로 보내지 않고 저장하지도 않는다(`localStorage`, 쿠키, IndexedDB 모두 안 씀).
  - 콘텐츠 보안 정책(CSP) `<meta>`로 `connect-src`, `img-src`, `font-src`, `form-action`을 모두 막아, 실수로 코드가 들어가도 바깥으로 나가지 못하게 한다.
  - 입력칸에 `spellcheck="false"`, `autocomplete="off"`를 준다. 브라우저의 고급 맞춤법 검사가 입력 내용을 서버로 보내는 일을 막기 위해서다.
- **배포:** GitHub Pages가 Jekyll 처리를 하지 않도록 저장소 맨 위에 빈 `.nojekyll` 파일을 둔다.

## 집계 규칙

| 항목 | 규칙 |
|---|---|
| 입력 형식 | 엑셀 복사 형식: 칸은 탭, 줄은 `\n` 또는 `\r\n`. 줄바꿈이나 탭이 든 칸을 엑셀이 `"…"`로 감싸 주는 형식도 읽는다. |
| 첫 줄 | 머리글. 둘째 열부터가 문항이다. |
| 첫 열 | 응답번호. 집계하지 않는다. |
| 유효 | 앞뒤 공백을 지운 값이 `1` `2` `3` `4` `5` 중 하나 |
| 빈 응답 | 칸이 비었거나 공백만 있음 |
| 제외 | 그 밖의 모든 값(`0`, `6`, `3.5`, `4.0`, `１`(전각), `네` 등) |
| 모자란 칸 | 칸 수가 머리글보다 적은 줄은 모자란 칸을 빈 응답으로 센다 |
| 평균 | 유효 응답의 합 ÷ 유효 응답 수. 소수 셋째 자리에서 반올림해 둘째 자리까지 쓴다(예: `3.00`, `2.68`). 유효가 0이면 `-` |

결과 표의 열은 **문항 / 유효 응답 / 평균 / 빈 응답 / 제외** 순서다.

### 규칙이 정하지 않은 경우에 대한 결정

- **맨 끝의 빈 줄:** 엑셀 복사본은 마지막에 줄바꿈이 붙는다. 데이터 맨 끝의 완전히 빈 줄(글자가 하나도 없는 줄)은 응답으로 치지 않는다. 그 외의 줄은 규칙대로 센다. 중간의 빈 줄은 "모든 칸이 모자란 줄"로 보고 전부 빈 응답으로 센다.
- **칸이 머리글보다 많은 줄:** 넘치는 칸은 집계하지 않는다. 결과 표 위의 요약에 그런 줄 수를 알려 준다.
- **반올림 정확도:** 부동소수점 오차(예: 2.675가 2.67로 내려가는 문제)를 피하려고 정수 계산으로 반올림한다.
- **머리글 이름:** 앞뒤 공백을 지워 표시한다. 비어 있으면 `(N열)`로 표시한다. 화면에는 `textContent`로만 넣어 HTML로 해석되지 않게 한다.
- **문항이 없을 때:** 머리글이 한 열뿐이거나 입력이 비어 있으면 표 대신 안내 문구를 보여 준다.

## 구조

- `index.html`
  - `<script id="tally-core">`: 화면과 무관한 순수 함수(`parseTsv`, `classifyCell`, `formatAverage`, `tally`). DOM을 만지지 않는다.
  - 그다음 `<script>`: 입력칸을 읽어 `tally` 결과를 표로 그린다.
- `test/tally.test.js`: `index.html`에서 `tally-core` 블록을 꺼내 Node의 `vm`에서 실행하고 계산을 시험한다. 그래서 시험 대상이 실제 배포 파일과 늘 같다.
- `test/static.test.js`: `index.html`에 외부 주소, 외부 스크립트·스타일·글꼴, 네트워크·저장소 API가 없는지 검사한다. `.nojekyll`이 비어 있는지도 본다.
- 시험은 Node 내장 시험 도구(`node --test`)를 쓴다. 설치할 패키지가 없다.
- `.github/workflows/test.yml`: PR과 푸시마다 시험을 돌린다.

## 작업 순서 (작업마다 커밋)

1. 계획서와 `.nojekyll` 추가
2. 계산 로직과 계산 시험
3. 화면(붙여넣기, 결과 표)
4. 정적 검사 시험, CI, README
5. 시험이 통과하면 PR 생성
